# Senior Full-Stack Academy

An independently readable .NET, React, and DSA learning library. The course is generated in small units and stored in Git. Open this folder as an Obsidian vault or read Markdown directly on GitHub.

## Curriculum and production status

The scope map has 12 tracks and 208 atomic topics. Each topic has its own JSON manifest under `curriculum/manifests/`; the learning path orders all 208 topics and the queue contains 2,119 lesson units, including one separate unit for each named DSA problem. The overview comes before the item-by-item references. All 208 manifests have source-backed inventories and are enabled for draft generation. Thirty-two DSA topics include 213 named problems; Actions compiles and runs each problem's C# assertions before committing it. The cloud curriculum separates provider-neutral foundations, Azure, and AWS. The system-design track adds eight topics, 56 case exercises, the HLD Handbook's 67 named technologies across 21 references, 22 standalone tradeoff references, and an expanded AI/ML inventory. The learning path puts intermediate DSA before the web stack while keeping its prerequisites explicit.

The model must not be asked to discover API names from memory. Each frozen manifest contains the exact names and versioned scope directly in the prompt payload, with checked source references recorded in the repo. The generator's job is to explain only those supplied items and must not add names. The overview lesson first teaches the purpose, mental model, parts, and a running example without requiring API memorization. For large platforms, define an edition, package, namespace, API family or documentation boundary first. Unbounded “everything” is not a checkable requirement. Missing concept maps or source inventories block generation. Recent major changes are stored as concrete named changes with release/source data and included only where relevant.

GitHub Actions starts a small automatic batch when curriculum manifests or authoring rules change, then continues with six scheduled runs per day. The push-triggered run is capped at four lessons and eight total Gemini requests; scheduled and manual runs are capped at 80 lessons and 160 requests. The configured pool uses the six model IDs currently exposed by this project: Gemini 3.5 Flash-Lite and 3.1 Flash-Lite (500 RPD each), plus Gemini 3.8 Flash, 3.6 Flash, 3 Flash, and 4 Hydrogen (20 RPD each). The two Gemini 2.5 endpoints returned unavailable for this project and were removed. `curriculum/model-usage.json` records successful calls per model and resets at midnight Pacific, as [Google's rate-limit docs specify](https://ai.google.dev/gemini-api/docs/rate-limits); the generator skips exhausted models and caps each run to the remaining known daily allowance. Six scheduled runs use at most 960 requests against the pool's observed 1,080 RPD total, while push-triggered and manual batches draw only from what remains. The API's own quota responses account for calls made outside this repository. Retries, second-pass reviews, and revisions count against the same per-run request budget. Draft checks require exact headings, cited manifest sources, included reference names, and paths confined to the draft folder; DSA C# programs are also compiled and run with their assertions. Automated content review checks each lesson against its frozen manifest but does not establish factual accuracy. `npm run validate:catalog` checks that all 208 topics have complete inventories.

GitHub Actions uses the configured model pool through the repository secret `GEMINI_API_KEY` and the free-tier limits currently visible in Google AI Studio. Quotas, model IDs, and GitHub scheduling are subject to provider limits. No billing should be enabled if a zero API bill is required.

## Read the course

Open `course/` by track, or inspect `curriculum/learning-path.json`, `curriculum/catalog.json`, and `curriculum/queue.json` for the planned scope. Generated files under `course/drafts/` are checked-shape drafts, not independently verified course material. The three original pilot lessons carry failure warnings. The 213 named DSA problem units include constraints, hints, C# solutions, dry runs, proofs, complexity analyses, and edge-case assertions. `curriculum/factual-review-ledger.json` tracks the required manual claim-by-claim audit; no lesson is promoted based on structural or AI checks alone. The committed content remains accessible without Codex.

Generated text remains draft material until claim-by-claim review is complete. DSA solution programs are compiled and their embedded assertions executed before commit; this does not establish that every algorithm explanation or factual claim is correct. AI review alone cannot establish factual accuracy. Do not use generated security guidance as the sole source of truth.

## Local development

Requires Node.js 20+. `npm test` runs offline checks. `npm run build:queue` regenerates the lesson sequence from the catalog and topic manifests. `npm run validate:structure` checks the index and queue. `npm run validate:catalog` audits full readiness and passes when all manifests are complete. `npm run generate` processes eligible units within a hard 100-request default budget; GitHub Actions runs it six times per day with an alternating two-model 160-request per-run cap, using the `GEMINI_API_KEY` repository secret and committing checked-shape drafts under `course/drafts/`.
