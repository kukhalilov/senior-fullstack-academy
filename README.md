# Senior Full-Stack Academy

An independently readable .NET, React, and DSA learning library. The course is generated in small units and stored in Git. Open this folder as an Obsidian vault or read Markdown directly on GitHub.

## Curriculum and production status

The scope map has 11 tracks and 161 atomic topics. Each topic has its own JSON manifest under `curriculum/manifests/`; the learning path orders all 161 topics in ten stages, and the queue has 905 units, including one separate unit for each named DSA problem. The overview comes before the item-by-item reference. Comparisons and recent release notes are optional topic data, not forced lesson types. Thirteen manifests now have source-backed inventories; twelve are fully enabled for draft generation, and one DSA analysis topic keeps its practice unit blocked. Five DSA topics are enabled for overviews, concepts, references, interviews, and 32 named problems; Actions will compile and run each problem's C# assertions before committing it. The other 148 inventories are incomplete. The learning path puts intermediate DSA before the web stack while keeping its prerequisites explicit.

The model must not be asked to discover API names from memory. Before reference generation, a frozen manifest must contain the exact names and versioned scope directly in the prompt payload, with checked source references recorded in the repo. The generator's job is to explain only those supplied items and must not add names. The overview lesson first teaches the purpose, mental model, parts, and a running example without requiring API memorization. For large platforms, define an edition, package, namespace, API family or documentation boundary first. Unbounded “everything” is not a checkable requirement. Missing concept maps or source inventories block generation. Recent major changes are stored as concrete named changes with release/source data and included only where relevant.

Scheduled GitHub Actions rebuilds the queue from manifests and generate draft lessons for explicitly enabled topics. Twelve topics are fully enabled; the DSA analysis practice unit remains blocked until it receives its own executable checks; 148 topic inventories are incomplete. Four automatic runs per day each have a hard budget of 100 Gemini API requests, including retries, second-pass reviews, and revisions. Draft checks require exact headings, cited manifest sources, included reference names, and paths confined to the draft folder; DSA C# programs are also compiled and run with their assertions. An automated content-review pass checks each lesson against its frozen manifest before commit. These automated checks cannot establish all factual accuracy. The three original pilot lessons failed quality review and remain quarantined. `npm run validate:catalog` intentionally fails until all 161 topics have complete, frozen inventories.

GitHub Actions uses the stable `gemini-3.5-flash-lite` model with the repository secret `GEMINI_API_KEY` and only models with available free-tier quota in Google AI Studio. Quotas, model IDs, and GitHub scheduling are subject to provider limits. No billing should be enabled if a zero API bill is required.

## Read the course

Open `course/` by track, or inspect `curriculum/learning-path.json`, `curriculum/catalog.json`, and `curriculum/queue.json` for the planned scope. Generated files under `course/drafts/` are checked-shape drafts, not independently verified course material. The three original pilot lessons carry failure warnings. Thirty-two named DSA problem units are queued to produce constraints, hints, C# solutions, dry runs, proofs, complexity analyses, and edge-case assertions. The committed content remains accessible without Codex.

Generated text remains draft material. DSA solution programs are compiled and their embedded assertions executed before commit; this does not establish that every algorithm explanation or factual claim is correct. AI review alone cannot establish factual accuracy. Do not use generated security guidance as the sole source of truth.

## Local development

Requires Node.js 20+. `npm test` runs offline checks. `npm run build:queue` regenerates the lesson sequence from the catalog and topic manifests. `npm run validate:structure` checks the index and queue. `npm run validate:catalog` audits full readiness and intentionally fails while inventories are incomplete. `npm run generate` processes eligible units within a hard 100-request budget; GitHub Actions runs it on a schedule using the `GEMINI_API_KEY` repository secret and commits checked-shape drafts under `course/drafts/`.
