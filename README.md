# Senior Full-Stack Academy

An independently readable .NET, React, and DSA learning library. The course is generated in small units and stored in Git. Open this folder as an Obsidian vault or read Markdown directly on GitHub.

## Curriculum and production status

The scope map has 11 tracks and 200 atomic topics. Each topic has its own JSON manifest under `curriculum/manifests/`; the learning path orders all 200 topics in ten stages, and the queue has 1,864 units, including one separate unit for each named DSA problem. The overview comes before the item-by-item reference. Comparisons and recent release notes are optional topic data, not forced lesson types. 165 manifests have source-backed inventories: 164 are fully enabled for draft generation, and one DSA analysis topic keeps its practice unit blocked. Thirty-two DSA topics are enabled for overviews, concepts, references, interviews, and 213 named problems; Actions will compile and run each problem's C# assertions before committing it. The other 35 inventories are incomplete. The cloud curriculum now separates provider-neutral foundations, Azure, and AWS. The learning path puts intermediate DSA before the web stack while keeping its prerequisites explicit.

The model must not be asked to discover API names from memory. Before reference generation, a frozen manifest must contain the exact names and versioned scope directly in the prompt payload, with checked source references recorded in the repo. The generator's job is to explain only those supplied items and must not add names. The overview lesson first teaches the purpose, mental model, parts, and a running example without requiring API memorization. For large platforms, define an edition, package, namespace, API family or documentation boundary first. Unbounded “everything” is not a checkable requirement. Missing concept maps or source inventories block generation. Recent major changes are stored as concrete named changes with release/source data and included only where relevant.

GitHub Actions starts a small automatic batch when curriculum manifests or authoring rules change, then continues with six scheduled runs per day. The push-triggered run is capped at four lessons and eight total Gemini requests; scheduled runs are capped at 80 lessons and 160 requests. Requests alternate between Gemini 3.5 Flash-Lite and Gemini 3.1 Flash-Lite, keeping one update plus six scheduled runs to at most 484 requests per model per day against the observed 500 RPD limit. Retries, second-pass reviews, and revisions count against the same hard request budget. Draft checks require exact headings, cited manifest sources, included reference names, and paths confined to the draft folder; DSA C# programs are also compiled and run with their assertions. An automated content-review pass checks each lesson against its frozen manifest before commit. These automated checks cannot establish all factual accuracy. The three original pilot lessons failed quality review and remain quarantined. `npm run validate:catalog` intentionally fails until all 200 topics have complete, frozen inventories.

GitHub Actions alternates requests between `gemini-3.5-flash-lite` and `gemini-3.1-flash-lite`, using the repository secret `GEMINI_API_KEY` and the free-tier limits currently visible in Google AI Studio. Quotas, model IDs, and GitHub scheduling are subject to provider limits. No billing should be enabled if a zero API bill is required.

## Read the course

Open `course/` by track, or inspect `curriculum/learning-path.json`, `curriculum/catalog.json`, and `curriculum/queue.json` for the planned scope. Generated files under `course/drafts/` are checked-shape drafts, not independently verified course material. The three original pilot lessons carry failure warnings. Two hundred thirteen named DSA problem units are queued to produce constraints, hints, C# solutions, dry runs, proofs, complexity analyses, and edge-case assertions. The committed content remains accessible without Codex.

Generated text remains draft material. DSA solution programs are compiled and their embedded assertions executed before commit; this does not establish that every algorithm explanation or factual claim is correct. AI review alone cannot establish factual accuracy. Do not use generated security guidance as the sole source of truth.

## Local development

Requires Node.js 20+. `npm test` runs offline checks. `npm run build:queue` regenerates the lesson sequence from the catalog and topic manifests. `npm run validate:structure` checks the index and queue. `npm run validate:catalog` audits full readiness and intentionally fails while inventories are incomplete. `npm run generate` processes eligible units within a hard 100-request default budget; GitHub Actions runs it six times per day with an alternating two-model 160-request per-run cap, using the `GEMINI_API_KEY` repository secret and committing checked-shape drafts under `course/drafts/`.
