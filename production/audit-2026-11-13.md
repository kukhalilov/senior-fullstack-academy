# Curriculum and lesson audit

## Findings

The original 65 broad modules and 260 phase files are not an API, method, attribute, or feature inventory. A topic can be marked complete based on headings and a 1,500-character threshold; existing lessons should be considered draft introductions, not comprehensive coverage. There is no automated evidence that each API or overload is covered, version-aware source verification, tested examples, or separate learner-facing DSA problem harness. The generic prompt repeats sections across phases and does not supply a detailed scope. Its second model pass does not establish correctness.

`curriculum/coverage.json` identifies 149 more granular curriculum targets. They are all marked missing pending evidence, including targets that overlap introductory drafts. This is not yet an exhaustive member inventory; determine supported versions and enumerate APIs from authoritative documentation before marking any item complete.

## Sample findings and corrections

- Variance foundations: invented `IAction<T>` was replaced with `Action<T>`; fixed overbroad descriptions of variance positions and mutable underlying objects. Source: https://learn.microsoft.com/dotnet/standard/generics/covariance-and-contravariance. The lesson still needs a detailed language specification coverage pass.
- Async practice: corrected claims that await always returns a thread to the thread pool and that an unawaited task necessarily runs in the background. Source: https://learn.microsoft.com/dotnet/csharp/asynchronous-programming/task-asynchronous-programming-model. Other timing and cancellation statements remain to be checked.
- HTTP foundations: clarified that HTTP/1.1 has textual syntax, HTTP/2 and HTTP/3 use binary framing, and HTTP/3 uses QUIC; the section requires a full protocol review.

## Remaining work

Build version-specific official source inventories down to API/member/attribute level; map each required entry to generated units, split large topics, implement objective-level completion and missing coverage tasks, check citations against real source pages, compile executable samples, and independently review all previously generated content. Coverage.json is a tracking start, not proof that every topic or API has been captured or verified.
