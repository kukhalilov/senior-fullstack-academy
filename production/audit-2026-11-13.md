# Curriculum and lesson audit

## Historical findings

The initial generation experiment produced broad lessons with section/length checks and an AI revision pass. These controls did not establish factual accuracy, API completeness, current-version coverage, or runnable examples. The three pilot lessons remain quarantined and do not count as course material.

## Current structure

The old `coverage.json` scope map has been removed. `curriculum/catalog.json` now indexes 157 topic manifests and `curriculum/queue.json` plans 799 small lesson units. Each topic sequence begins with an overview and concept lesson, then one or more bounded reference lessons, practice, and interview preparation. Version notes are optional manifest data.

JavaScript values/types, Array, and C# program structure are the first source-backed inventory examples. Values/types lists the eight ECMAScript language types and excludes specification-only algorithm types. Array records a concept map, a bounded ECMAScript 2026 scope, 48 exact names across ten reference groups, and recent relevant edition changes. The other 153 topic manifests are incomplete; the DSA complexity inventory is held back from generation until C# solutions can be checked. `npm run validate:catalog` must fail while any topic lacks its complete source-backed concept map and inventory. Scheduled draft generation is enabled only for three source-backed manifests; whole-catalog generation remains blocked.

## Sample findings and preserved warnings

- Variance foundations: an invented `IAction<T>` was replaced with `Action<T>`; variance positions and mutable underlying objects still need full spec-level review. Source: https://learn.microsoft.com/dotnet/standard/generics/covariance-and-contravariance.
- Async practice: corrected claims that `await` always returns a thread to the thread pool and that an unawaited task necessarily runs in the background. Source: https://learn.microsoft.com/en-us/dotnet/csharp/asynchronous-programming/task-asynchronous-programming-model.
- HTTP foundations: clarified HTTP/1.1 textual syntax, HTTP/2 and HTTP/3 binary framing, and HTTP/3 over QUIC; the entire section still requires review.
