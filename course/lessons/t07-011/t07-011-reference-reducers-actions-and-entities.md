
# React Redux Toolkit store slices selectors middleware and async workflows — Reference: Reducer, action, slice, and normalized entity APIs

# Scope and version

This is a bounded reference to the supplied RTK reducer/action/entity names. RTK 2 uses builder callback notation for `extraReducers`; the older object notation is removed. `createSlice` remains the standard feature-reducer approach. See [createSlice](https://redux.js.org/toolkit/api/createSlice), [createReducer](https://redux.js.org/toolkit/api/createReducer), [createAction](https://redux.js.org/toolkit/api/createAction), and [createEntityAdapter](https://redux.js.org/toolkit/api/createEntityAdapter).

# How this group fits the mental model

Actions describe events, and reducers calculate state transitions. A slice packages feature-local transitions and generated actions. Entity adapters standardize common operations on normalized collections. Immer lets RTK reducers use draft assignment while still producing immutable state.

# Supplied names explained

- `createSlice(options)` — Creates a slice reducer, action creators for its reducer cases, selectors, and metadata. Current options are `name`, `initialState`, `reducers`, `extraReducers`, `reducerPath`, and `selectors`.
- `createSlice.reducers` — The object of case reducer definitions for actions owned by the slice. RTK creates action creators whose type uses the slice name and reducer key.
- `createSlice reducers prepare callback` — A reducer entry may be `{ reducer, prepare }`; `prepare` transforms creator arguments into the action payload and optional metadata, while `reducer` handles the action. Generate IDs in `prepare`, outside the pure reducer.
- `createSlice reducers creator callback` — RTK 2 also accepts `reducers: (create) => ({ ... })`, exposing typed reducer creators and async-thunk creation.
- `buildCreateSlice({ creators })` — Builds a customized `createSlice` that can include optional creators such as async thunks. The ordinary export omits that code unless requested.
- `create.reducer(reducer)` — Creator-callback helper for defining a typed case reducer.
- `create.preparedReducer(prepare, reducer)` — Creator-callback helper combining a prepare callback and reducer, with payload type inferred from the prepare result.
- `create.asyncThunk(payloadCreator, lifecycleReducers?)` — Optional helper for defining a thunk inside a slice. Enable it with `buildCreateSlice` and `asyncThunkCreator`; the ordinary `createSlice` export throws if used without this setup.
- `create.asyncThunk settled reducer` — Optional finalizer for both fulfilled and rejected outcomes, after their specific lifecycle reducers, like a `finally` step.
- `createSlice.extraReducers builder callback` — Builder form for responding to actions not generated by this slice, including async thunk lifecycle actions and action matchers. It does not generate action creators for those cases.
- `createSlice.name` — Namespace prefix used to create action type strings, such as `todos/itemAdded`. Keep it stable because it becomes part of the action contract.
- `createSlice.reducerPath` — Preferred state key used by slice selectors and `combineSlices`; it defaults to `name`. It does not force a manually composed reducer map to use that key.
- `createSlice.selectors` — Selectors supplied in the slice options, wrapped to read the state under `reducerPath`. Their unwrapped selector is available on the wrapped selector's `.unwrapped` field.
- `createSlice returned selectSlice` — Selector that reads this slice from a root state at `state[reducerPath]`. It is the default locator used by generated `slice.selectors`.
- `createSlice returned getSelectors(selectState?)` — Returns slice selectors unwrapped when called without an argument, or wraps them with the supplied root-state-to-slice-state callback.
- `createSlice returned getInitialState()` — Returns the initial slice value; when a lazy initializer was supplied, this invokes it and produces a fresh initial value.
- `createSlice returned injectInto(combinedReducer, config?)` — Injects the slice into a `combineSlices` reducer and returns an injected-slice view. It supports code splitting; injection does not synchronously replace store state.
- `createSlice.initialState` — Initial state value or lazy initializer. It is used when the reducer receives `undefined`; it is not a reset mechanism on arbitrary state.
- `createSlice.actions` — Generated action creators corresponding to entries in `reducers`; their `.type` identifies the event and their argument becomes payload according to the reducer definition.
- `createSlice.reducer` — The reducer function to register under a root state key. The state key is chosen by store composition and need not equal the slice name, though matching them is conventional.
- `createSlice.caseReducers` — The individual case reducer functions exposed for reuse or testing. They operate on Immer drafts when invoked by the slice reducer; calling them directly with ordinary state does not automatically provide Immer wrapping.
- `createAction(type)` — Creates an action creator for a specified string type. RTK action creators include a `.type` field and a `.match(action)` type guard. Prefer slice-generated creators when the action belongs to a slice.
- `createAction prepare callback` — Optional second argument transforms creator arguments into `{ payload, meta?, error? }`; it centralizes action construction while reducers remain pure.
- `actionCreator.match(action)` — Runtime type predicate that checks the action type and narrows its type in TypeScript.
- `createReducer(initialState, builderCallback)` — Builds a reducer using builder methods such as `.addCase`, `.addMatcher`, and `.addDefaultCase`, with Immer draft support. It is useful when transitions are not naturally grouped into a slice or need to respond to many external actions.
- `createReducer builder.addCase(actionCreator, reducer)` — Adds one exact action-type case. Register all exact cases before matchers or a default case.
- `createReducer builder.addMatcher(matcher, reducer)` — Adds a predicate case for a family of actions; matching cases run in registration order after exact cases.
- `createReducer builder.addDefaultCase(reducer)` — Handles an action only if no exact case or matcher handled it; it is not a general initializer.
- `createReducer builder.addAsyncThunk(asyncThunk, reducers)` — Groups lifecycle reducers for one async thunk. Register it before other builder cases according to the builder ordering rules.
- `PayloadAction<T>` — RTK/Redux Toolkit TypeScript action shape whose `payload` has type `T`; action metadata and error fields may also be present. Do not confuse a static TypeScript type with a runtime validator.
- `Immer draft mutation in case reducers` — Assigning to a draft, calling draft-mutating methods, or deleting draft fields is translated into an immutable next state. Do not mutate and return a different replacement in the same case. A returned replacement is appropriate when replacing the whole state; primitive state reducers must return the new primitive.
- `createEntityAdapter(options)` — Creates helpers for a normalized entity collection, including an initial state shape, CRUD case reducers, selectors, ID extraction, and optional sorting.
- `entityAdapter.addOne(state, entity)` — Inserts one entity only if its ID is absent; it leaves an existing entity unchanged.
- `entityAdapter.addMany(state, entities)` — Adds missing entities from an array or ID-keyed record without replacing existing IDs.
- `entityAdapter.setOne(state, entity)` — Inserts or fully replaces one entity, dropping old fields absent from the replacement.
- `entityAdapter.setMany(state, entities)` — Inserts or fully replaces entities from an array or ID-keyed record.
- `entityAdapter.setAll(state, entities)` — Replaces the whole entity collection and ID list with the supplied collection.
- `entityAdapter.removeOne(state, id)` — Removes an entity and ID if present.
- `entityAdapter.removeMany(state, ids or { where })` — Removes an ID list or, in RTK 2.14, entities whose string-keyed fields strictly equal all fields in `{ where }`. An empty filter matches nothing.
- `entityAdapter.removeAll(state)` — Clears the entity collection while preserving extra state fields on an extended entity state.
- `entityAdapter.updateOne(state, { id, changes })` — Shallow-merges changes into the matching entity and ignores a missing ID. Nested objects are replaced, not deep-merged.
- `entityAdapter.updateMany(state, updates)` — Applies shallow `{ id, changes }` updates; repeated updates for an ID merge, with later values winning.
- `entityAdapter.upsertOne(state, entity)` — Adds a missing entity or shallow-merges the supplied fields into an existing entity.
- `entityAdapter.upsertMany(state, entities)` — Adds or shallow-merges multiple entities from an array or ID-keyed record.
- `entityAdapter.selectByIds(state, ids)` — Added in RTK 2.14; returns found entities in requested ID order, skips missing IDs, and memoizes stable inputs.
- `entityAdapter.getSelectors(selectState?, { createSelector? })` — The optional second argument supplies a selector creator; preserve draft-safe behavior if selectors may run on Immer drafts.
- `entityAdapter.getInitialState()` — Returns the standard `{ ids: [], entities: {} }` state (plus any supplied extra state). Use it to establish the adapter's expected shape.
- `entityAdapter.getSelectors(selectState?)` — Creates selectors for adapter state. Without `selectState`, selectors accept the entity state itself; with it, they accept root state and locate the entity slice. Current RTK selectors include `selectIds`, `selectEntities`, `selectAll`, `selectTotal`, `selectById`, and `selectByIds`; an optional second argument can supply a custom selector creator.
- `entityAdapter.selectId` — Optional entity ID selector used to determine each entity's key. Default behavior reads `entity.id`; supply a custom function when the domain's stable key differs. IDs must be strings or numbers.
- `entityAdapter.sortComparer` — Optional comparator that keeps `ids` sorted as adapter operations run. Sorting adds work to updates and should reflect a stable domain ordering.

# Cross-item comparison

`createSlice(options)` is usually clearest for one feature's state and own actions. `createReducer(initialState, builderCallback)` defines a reducer without requiring a slice's action-generation convention. `createAction(type)` can define an event shared across reducers. They all ultimately create ordinary Redux actions/reducers; the choice is about organization and action ownership.

Normalized adapter state is not the same as a database. It provides consistent in-memory entity lookup and updates. `sortComparer` maintains a chosen ID order, while `selectAll` presents an array; do not assume entity object insertion order is a meaningful UI order when none is specified.

# Examples

```ts
const tasksAdapter = createEntityAdapter<Task>({
  selectId: task => task.taskId,
  sortComparer: (a, b) => a.title.localeCompare(b.title),
})

const tasksSlice = createSlice({
  name: 'tasks',
  initialState: tasksAdapter.getInitialState({ status: 'idle' as 'idle' | 'loading' }),
  reducers: {
    taskUpserted: tasksAdapter.upsertOne,
    taskRemoved: tasksAdapter.removeOne,
  },
  extraReducers: builder => {
    builder.addCase(importFinished, (state, action) => {
      tasksAdapter.setAll(state, action.payload)
      state.status = 'idle'
    })
  },
})
```

The adapter methods used as case reducers receive the slice draft and action payload. In a full app, validate external/imported data before it reaches reducers.

# Common mistakes

- Mutating state in ordinary functions while assuming Immer applies outside RTK case reducers.
- Mixing draft mutation with returning a replacement from the same case reducer.
- Expecting `extraReducers` to create actions; it only handles external actions.
- Treating `PayloadAction<T>` as runtime input validation.
- Using an unstable or missing entity ID, or sorting with a comparator that changes unpredictably.
- Storing copies of the same entity in several slices instead of referencing the canonical entity by ID.

# Knowledge checks with answers

1. Which part creates actions for slice-owned cases? **`createSlice.reducers`, exposed through `createSlice.actions`.**
2. Does `extraReducers` generate its handled action? **No; it handles actions defined elsewhere.**
3. What is the adapter's standard state shape? **An `ids` array plus an `entities` lookup, optionally extended with extra state.**
4. Can a case reducer both mutate the draft and return a replacement? **No; choose one update style per case.**
