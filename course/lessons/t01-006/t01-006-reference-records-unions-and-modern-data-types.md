
# C# classes structs records constructors and initialization — Reference: Positional records, synthesized members, unions, and closed type declarations

# Scope and version
This lesson covers modern C# data structures, including records, union types, and closed class hierarchies as defined in C# 15 and .NET 11 (GA 2026-11-14). It focuses on how these types manage state, equality, and hierarchy.

# How this group fits the mental model
In C#, types define the "contract" (what an object can do) and the "representation" (how it stores data). 
- **Records** simplify data-oriented programming by synthesizing equality and copying logic.
- **Unions** provide a way to define a type that represents one of several specific cases, ensuring type-safe handling of varied data.
- **Closed hierarchies** allow developers to restrict inheritance to a specific assembly, providing control over how a type hierarchy is extended.

These features move away from manual boilerplate code toward declarative, compiler-generated implementations.

# Supplied names explained

* `Positional record class`: A reference type record that uses a primary constructor to define its data members.
* `Nominal record class`: A reference type record defined using standard property syntax rather than positional parameters.
* `Positional record struct`: A value type record that uses a primary constructor to define its data members.
* `Nominal record struct`: A value type record defined using standard property syntax.
* `Record primary constructor`: The constructor defined in the record declaration header that initializes the record's state.
* `Record positional parameter`: A parameter in the primary constructor that automatically generates a corresponding property.
* `Synthesized record property`: A property generated by the compiler for a positional record parameter.
* `Synthesized Deconstruct method`: A generated method that allows deconstructing a record into its individual components.
* `Synthesized record equality`: The compiler-generated logic that compares records based on their values rather than reference identity.
* `Synthesized equality operator`: The generated `==` and `!=` operators that use value-based comparison.
* `Synthesized GetHashCode method`: A generated method that produces a hash code based on the record's state.
* `EqualityContract property`: A synthesized protected property on record classes used in record equality to distinguish runtime record types in an inheritance hierarchy. Record structs have no inheritance hierarchy and do not use this member.
* `Record with expression`: Syntax used to create a non-destructive copy of a record with specific properties modified.
* `Record init-only property`: A property that can only be set during object initialization.
* `Record class inheritance`: The ability for a record class to inherit from another record class.
* `Record struct inheritance restriction`: The rule that record structs cannot inherit from other types.
* `Record value equality`: The behavior where two records are equal if their properties have equal values.
* `Record shallow copy`: The behavior of the `with` expression, which copies the record's values but does not perform a deep copy of referenced objects.
* `Union declaration`: A type definition that represents one of several distinct cases.
* `union keyword`: The keyword used to define a union type.
* `Union case type`: A specific type variant within a union.
* `Union case value`: The actual data held by a specific union case.
* `Union implicit case conversion`: The ability to treat a case as the union type automatically.
* `Union exhaustive switch expression`: A switch expression that handles every declared case type; nullable union values also require a `null` arm.
* `Union pattern match`: Using pattern matching to extract data from a union case.
* `Union case conversion`: The process of casting or converting between union cases.
* `Union generated API surface`: The set of methods and properties generated by the compiler for a union.
* `Closed class modifier`: A modifier that restricts inheritance of a class to its defining assembly.
* `closed class hierarchy`: A set of types where the derivation is restricted to a specific assembly.
* `Closed class direct descendant`: A class that inherits directly from a closed class within the same assembly.
* `Closed hierarchy exhaustiveness`: The compiler's ability to verify that all possible subtypes of a closed hierarchy are handled.
* `Closed class assembly boundary`: The scope within which inheritance of a closed class is permitted.
* `Closed modifier restrictions`: Rules limiting where the closed modifier can be applied.
* `C# 15 memory safety preview feature`: A preview language feature set (not a .NET 11 GA guarantee) that changes `unsafe` context requirements and adds safety annotations/keywords under preview language and feature flags; dereferencing/accessing unmanaged memory remains unsafe. This is distinct from `ref struct` lifetime safety.
* `C# 15 collection expression with-element (with(...))`: A collection-expression element that supplies constructor/factory arguments to the target collection, such as capacity or comparer; it does not represent an item stored in the collection.
* `C# 15 extension indexer`: An indexer declared inside an extension block so callers can index a receiver as if it declared the indexer; an extension indexer requires a named receiver parameter.
* `C# 15 non-virtual static interface member on older runtime`: A static interface member with a body that can be used on older target runtimes; default instance implementations, static abstract/virtual members, and protected interface members still require runtime support.
* `Data transfer object (DTO)`: A pattern for objects that carry data between processes.
* `Value object type`: A type defined by its data rather than its identity.
* `Entity type identity`: The concept that an object is defined by a unique identifier.
* `Immutable data type`: A type whose state cannot be changed after creation.
* `Mutable object graph`: A structure of objects where internal state can be modified.
* `Record versus class`: A comparison of reference-based identity versus value-based equality.
* `Record struct versus struct`: A comparison of value-based equality features in structs.
* `Union versus nullable value`: A comparison of union types against simple nullable types.
* `Union versus inheritance hierarchy`: A comparison of union types against traditional polymorphism.
* `Closed hierarchy versus sealed class`: A comparison of assembly-restricted inheritance versus complete prohibition of inheritance.

# Cross-item comparison
- **Record modifier vs. class/struct semantics**: `record class` remains a reference type and `record struct` remains a value type. Records synthesize value equality; ordinary classes can also customize equality, so reference identity isn't guaranteed for every class.
- **Unions vs. Inheritance**: Unions provide a closed set of types that are easier to exhaustively switch over compared to open inheritance hierarchies.
- **Closed vs. Sealed**: A `sealed` class cannot be inherited; direct children of a `closed` class must be in the same assembly. Those children are not automatically closed or sealed, so descendants can remain open unless separately restricted.

# Examples
```csharp
// Positional record class
public record Person(string Name, int Age);

// Usage of with expression
var p1 = new Person("Alice", 30);
var p2 = p1 with { Age = 31 }; // Shallow copy with modification
```

# Common mistakes
- Assuming `with` expressions perform a deep copy; they only perform a shallow copy of the object graph.
- Attempting to inherit from a `record struct`, which is prohibited.
- Forgetting that `closed` classes are only restricted within the assembly; they are not `sealed`.

# Knowledge checks with answers
1. **Question**: What is the primary difference between a `record class` and a standard `class`?
   **Answer**: A `record class` provides synthesized value-based equality and `with` expression support, whereas a standard `class` uses reference identity.
2. **Question**: Can you inherit from a `record struct`?
   **Answer**: No, `record struct` inheritance is restricted.
3. **Question**: What does the `EqualityContract` property do?
   **Answer**: For record classes, it participates in synthesized equality so different runtime record types in an inheritance hierarchy aren't treated as equal solely because their base data matches. Record structs don't have this property.
