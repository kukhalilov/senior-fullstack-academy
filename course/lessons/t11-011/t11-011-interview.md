# graph models, representations, and traversal — Interview questions and reasoning

## Core questions

1. How do you represent a sparse graph?
2. Why is BFS shortest-path correct for unweighted graphs?
3. When must traversal restart from another vertex?
4. Why mark visited at discovery time?
5. How does multi-source BFS differ from repeated single-source BFS?
6. How do you test whether an undirected graph is bipartite?

## Concise interview answers

- An adjacency list stores vertices and neighbor entries in O(V+E) space.
- BFS explores in nondecreasing edge distance, so first discovery is shortest in an unweighted graph.
- Restart at each unseen vertex to enumerate all undirected connected components.
- Mark-on-enqueue ensures each vertex enters the frontier at most once.
- Multi-source BFS seeds all sources at distance zero and computes distance from the nearest source.
- Two-color every component; an edge joining same-colored endpoints proves a conflict.

## Deep follow-up answers

### Compare adjacency lists and matrices

Lists use O(V+E) space and traverse only present edges, which is effective for sparse graphs. Matrices use O(V²), but edge existence is O(1) and iterating a row is O(V); they may suit dense graphs or small fixed vertex sets. Edge lists are compact for processing edges globally but neighbor lookup is not direct.

### Why does BFS give shortest edge-count paths?

Queue order processes distance d before d+1. When an unvisited vertex is first reached from a distance-d vertex, a path of length d+1 is known. Any shorter path would have been explored in an earlier layer, so the first-discovery distance is minimal.

### Why mark on enqueue?

Several processed vertices can share a neighbor. If it is marked only on dequeue, each predecessor may enqueue another copy. Marking when first discovered establishes a single frontier entry and supports linear traversal work.

### What changes in directed graphs?

Adjacency follows outgoing arcs, so one-source traversal computes reachable vertices. Restarting from every vertex does not directly produce strongly connected components. Weak connectivity ignores direction; strong connectivity requires mutual directed reachability and needs a dedicated algorithm.

### How does grid flood fill fit graph traversal?

Each cell is a vertex; legal neighbor moves are edges generated by coordinate offsets. Marking cells when discovered gives the same component invariant as an explicit graph, without storing every edge.

## Scenario questions

1. **Need the shortest number of moves in an unweighted maze.** BFS from the source, storing distance or parent.
2. **Need to count land masses in a large grid.** Scan every cell and flood-fill each unseen land component.
3. **Need to duplicate a cyclic object graph.** Map original references to clone references before traversing neighbors.
4. **Need every connected group in an undirected graph.** Restart DFS/BFS for each unvisited vertex.
5. **Need to model spread from many initial locations.** Seed all sources in a multi-source BFS at distance zero.

## Tradeoffs and alternatives

- DFS and BFS have the same O(V+E) traversal bound with adjacency lists but answer different ordering needs.
- Recursive DFS is concise; iterative DFS avoids call-stack limits.
- BFS uses O(width/frontier) memory; DFS uses O(depth) stack or frontier.
- Disjoint-set union can answer undirected connectivity under edge additions but does not provide traversal paths.

## Common weak answers

- **“BFS is always the shortest path algorithm.”** It is shortest by edge count only when edges have equal costs.
- **“Start from vertex zero to count components.”** That misses disconnected components.
- **“Visited can be marked after processing.”** Duplicate frontier entries can inflate work and memory.
- **“An adjacency matrix is O(E).”** It stores V² cells, including nonedges.
- **“Same values mean same graph node.”** Identity is a reference/vertex label contract, not necessarily payload equality.
