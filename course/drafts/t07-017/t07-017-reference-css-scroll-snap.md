# CSS layout flexbox grid positioning and responsive design — Reference: CSS Scroll Snap properties

# Scope and version

This lesson explains all 25 supplied properties in **CSS Scroll Snap properties** and no additional inventory names. MDN descriptions and support labels were captured on 2026-11-16. 25 names have an MDN Baseline label, 0 have Limited availability, and 0 are explicitly marked Experimental in the 2026-11-16 capture. These labels can overlap; the row for every name preserves its own status. A missing Baseline label is not proof that no browser implements it. Support can change after this capture. The CSS Snapshot 2026 reports specification maturity rather than browser adoption. [W3C CSS Snapshot 2026](https://www.w3.org/TR/css-2026/)

# How this group fits the mental model

Scroll Snap defines preferred resting positions for a scroll container and its children. The browser retains control of scrolling physics and may account for gestures, focus, programmatic movement, and other priorities; snap is not a script-driven frame-by-frame animation. The overview and concepts lessons explain the surrounding layout model; this catalog now ties every supplied name to its role. A short MDN description is not a complete grammar. Follow the linked specification/reference for exact values, applicability, inheritance, computed-value rules, and browser-specific support before using an unfamiliar value.

# Cross-item comparison

`scroll-snap-type` establishes the container axis and strictness; `scroll-snap-align` marks a child’s snap area alignment; `scroll-padding` adjusts the snapport, often for fixed headers; `scroll-margin` expands a child’s snap area. Physical and logical longhands address different axes.

# Examples

For a horizontal card rail, make each card a start snap target, add scroll padding for an overlaying toolbar, and keep free scrolling possible. Do not force mandatory snapping if it prevents users from reaching content at unusual zoom or viewport sizes.

```css
.rail { overflow-x: auto; scroll-snap-type: x proximity; scroll-padding-inline: 1rem; }
.rail > * { scroll-snap-align: start; scroll-margin-inline: .25rem; }
```

The example illustrates a layout choice; adapt it to actual content and test target browsers, zoom, writing modes, keyboard use, and narrow containers.

# Common mistakes

- Expecting `scroll-snap-type` to define exact animation duration or physical momentum.
- Using `mandatory` where tall content can trap the reader between snap points.
- Confusing the container’s snapport adjustment with the target’s snap area.
- Treating `scroll-initial-target` as stable; it is a Scroll Snap Level 2 draft.
- Inferring a property’s full value grammar from its name or the brief definition alone.
- Assuming MDN support labels prove support in every browser version or embedded webview.
- Confusing the CSS Working Group draft status with a browser implementation guarantee.
