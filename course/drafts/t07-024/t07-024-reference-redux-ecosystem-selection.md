# Frontend state management Redux Toolkit and MobX comparisons — Reference: Redux Toolkit and RTK Query role

## Scope and version

This reference explains the supplied Redux Toolkit/RTK Query concepts at the ecosystem-selection level. Exact signatures and full behavior are taught in t07-011 and the official API references. [Redux Toolkit usage](https://redux.js.org/toolkit/usage/usage-guide) [RTK Query](https://redux.js.org/toolkit/rtk-query/overview)

## How this group fits the mental model

Redux Toolkit manages shared client state through explicit actions/reducers. RTK Query is an optional Redux Toolkit addon for backend-owned data fetching and cache lifecycle; it uses a generated API slice with reducer/middleware and can generate React hooks.

## Supplied names explained

- `Redux Toolkit store` holds the Redux state tree and combines reducer logic, middleware, and DevTools support.
- `configureStore` creates the store with good defaults including reducer composition, thunk middleware, development checks, and DevTools integration. It is the standard setup path.
- `createSlice` defines a state slice and reducer logic, generating action creators/types for its reducers. Reducer “mutations” are translated by Immer into immutable updates.
- `createSelector` creates a memoized selector for derived state. Use it when derivation is expensive or stable result identity matters, not as a substitute for a clear source of truth.
- `createAsyncThunk` generates lifecycle actions around an async function (pending/fulfilled/rejected) and supports handwritten request workflows. It does not automatically supply RTK Query's endpoint cache/subscription lifecycle.
- `createListenerMiddleware` reacts to dispatched actions/state changes and runs side effects with cancellation/async utilities. It is a Redux-specific workflow mechanism, not a general React Effect.
- `RTK Query` is an optional addon in Redux Toolkit for server-data fetching and caching, including request deduplication, subscriptions, generated hooks, and invalidation.
- `createApi(options)` defines an API slice, its base query, endpoints, cache configuration, and tag types. Import from `@reduxjs/toolkit/query/react` for generated React hooks; the core `@reduxjs/toolkit/query` entry point is UI-agnostic.
- `fetchBaseQuery(options)` is a small fetch-based base-query helper with common request/response handling. It is not mandatory; custom base queries can handle other transports/auth/retry behavior.
- `query endpoint` describes a read request and cached result for a parameterized query. Cache identity derives from endpoint plus serialized arguments; design arguments consistently.
- `mutation endpoint` describes a server write. It can invalidate tags or update cache data; server success does not remove the need to handle errors and concurrency.
- `generated query hook` is a React hook generated by the React-specific API entry point for a query endpoint, exposing data/loading/error/subscription behavior.
- `generated mutation hook` is a React hook generated for a mutation endpoint, returning a trigger function and mutation state.
- `tag-based cache invalidation` associates queries with provided tags and mutations with invalidated tags so affected cached data can refetch when subscribed. Tags are labels, not a database transaction or global cache purge.
- `API slice reducer and middleware` are generated by `createApi`: the reducer stores query/mutation cache state and middleware manages cache lifetimes, subscriptions, and endpoint behavior. Add both to the Redux store.
- `setupListeners(store.dispatch)` enables focus/reconnect listener behavior used by RTK Query options such as refetch-on-focus/reconnect. It is optional and must be set up in an appropriate browser environment.

## Cross-item comparison

`createAsyncThunk` gives explicit async lifecycle actions for custom workflows; `RTK Query` defines endpoint/cache/subscription behavior for server data. `configureStore`/`createSlice` manage client state; RTK Query's API slice manages cached server responses. The React-generated hooks are available only from the React-specific entry point.

## Examples

```ts
const api = createApi({
  reducerPath: 'projectsApi',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['Project'],
  endpoints: builder => ({
    getProject: builder.query({
      query: id => `projects/${id}`,
      providesTags: (_result, _error, id) => [{ type: 'Project', id }],
    }),
  }),
});
```

The snippet illustrates the API slice shape; add `api.reducer` and `api.middleware` to `configureStore`, and use the React entry point if you need generated hooks. [RTK Query API slice](https://redux.js.org/toolkit/rtk-query/api/created-api/overview)

## Common mistakes

- Treating RTK Query as required for Redux Toolkit.
- Importing the UI-agnostic core API and expecting generated React hooks.
- Adding the API reducer but forgetting its middleware.
- Using `createAsyncThunk` and assuming it automatically caches/deduplicates endpoint data.
- Designing tags too broadly or too narrowly, causing unnecessary/refused revalidation.
- Assuming `setupListeners` runs automatically.
- Storing form drafts or purely local UI flags in API cache state.

## Knowledge checks with answers

1. Is RTK Query optional? Yes.
2. Which entry point provides generated React hooks? `@reduxjs/toolkit/query/react`.
3. What two store pieces does an API slice provide? Reducer and middleware.
4. What does tag invalidation do? Marks related cached query data for refetch/revalidation when appropriate.
5. Does `createAsyncThunk` provide a server cache by itself? No.
